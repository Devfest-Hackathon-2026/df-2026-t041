## 1. 誰の、どんな課題か

**対象ユーザー：デザイナーのいない個人経営の飲食店の店主とスタッフ。**

個人店は、季節メニュー・日替わり・値上げのたびに、店頭POPやチラシ、SNS用の画像を作り直します。私たちが想定する店主の現状と困りごとは次のとおりです。

- 営業と仕込みの合間に作るので、1枚に長い時間をかけられない
- 汎用デザインツールはテンプレートが多すぎて、選んで直すだけで時間がかかる
- 画像生成AIで作ると、文字が崩れたり、入れていない価格や説明が紛れ込んだりする。店頭に出す情報としては危険
- 生成された画像は1枚絵なので、価格を1つ直すだけでも作り直しになる

> 補強のお願い：実際の店主への聞き取りや、身近な店の事例があれば、ここに追記してください。審査では「根拠付き」の課題説明が評価されます。

## 2. 解決策

商品名と価格を入れ、料理写真を載せて、「落ち着いた和食店の雰囲気で」のように一言書くだけで、Gemini が**編集できるレイアウトを3案**提案します。店主は自分で1案を選び、キャンバス上で文字も写真も自由に直せます。「値段をもっと大きく赤色に」と日本語で頼むと、AIは必要な要素だけを差分で直します。完成したら印刷用PDF（実寸・300dpi）か、SNS用PNGで保存します。

| 店主がやること | かかる時間（実測） |
| --- | --- |
| 内容と写真を入れて3案を受け取る | 約12〜20秒（Cloud Run 本番環境） |
| 日本語でAIに直してもらう | 約5〜10秒 |
| PNG / PDF で保存 | 数秒 |

## 3. テーマ「Own the Why, Build with Intent.」との関係

このプロダクトは、AIに決めさせるのではなく、**人が選び、人が直す**ことを前提に設計しています。

- **AIは複数案を出し、人が選ぶ。** 1案を押しつけず、必ず3案を並べます。
- **AIの出力を鵜呑みにしない。** 価格は入力値でサーバーが上書きし、AIが値段を書き換えられないようにしています。レイアウトも全要素をサーバーで検証し、はみ出しや不正な値を直してから表示します。
- **最終判断は人の手元に残る。** 生成後もすべての要素を手で編集でき、元に戻す・やり直しにも対応しています。

開発の進め方でも同じ方針を取りました。技術選定のたびに複数案を比べ、実測して決め、捨てた案と理由を次の節に残しています。

## 4. 技術選定の理由（採用した案・捨てた案・根拠）

### 4-1. AIに作らせるもの：完成画像か、レイアウトの設計図か

| 案 | メリット | デメリット | 判断 |
| --- | --- | --- | --- |
| 画像生成AIでチラシを1枚絵として作る | 見た目の完成度が高い | 文字や価格を後から直せない。1枚の生成に約40秒かかる。入れていない情報が描かれる恐れ | 不採用 |
| **AIはレイアウトの設計図（JSON）を作り、アプリが編集可能なキャンバスに組み立てる** | 文字が常に正確。全要素を後から編集できる。速い | 写真自体の加工はできない | **採用** |

根拠：開発中に画像生成モデルで同じ内容のチラシを試作しました。見た目は良いものの、価格の修正にも再生成が必要で、店頭での「すぐ直したい」に合いませんでした。

### 4-2. AIの呼び出し方：Gemini API キーか、Vertex AI か

| 案 | メリット | デメリット | 判断 |
| --- | --- | --- | --- |
| Google AI Studio の API キー | 設定が簡単 | 無料枠は1モデル1日20回で、公開デモには足りない。配布クレジットの対象外。キーの保管が必要 | 開発時のみ |
| **Vertex AI（Cloud Run のサービスアカウントで認証）** | APIキーを保存しない。配布クレジットの対象。IAM で権限を最小にできる | 課金の有効化が必要 | **採用** |

### 4-3. 応答速度：スキーマ制約付き生成か、JSONモード＋サーバー検証か

Vertex AI で、出力形式（JSON Schema）を指定した生成を実測したところ、3案の生成が150秒を超えてタイムアウトしました。スキーマはプロンプトで示し、出力の検証をサーバー側で行う方式に変えると、約12秒で返りました。さらに Gemini 3 の思考レベルを LOW にしました。レイアウトのJSONに深い推論は不要だと判断したためです。

| 方式 | 3案の生成時間（実測） |
| --- | --- |
| スキーマ制約付き生成 | 150秒以上（タイムアウト） |
| **JSONモード＋サーバー検証** | **約12〜20秒** |

### 4-4. AI出力の扱い：そのまま描画するか、検証して直すか

Gemini の出力を観察すると、次のような「意図はあるが仕様と違う」値が繰り返し現れました。そのまま描画すると、価格が紙面の外に出て見えなくなりました。

- 中央揃えの文字で、x 座標を「文字ボックスの左端」ではなく「中心点」として返す
- 色に `transparent`、線幅にピクセル値を返す
- 価格を大きくするよう頼むと、枠の幅を変えずに文字だけ大きくし、2行に折り返す
- 大きくした価格を説明文と同じ行に置き、文字どうしが重なる
- 追加した装飾の白い枠が、文字の上に重なる

そこで、AIの出力をサーバーで検証し、意図を推定して直す処理を入れました。

- はみ出した文字ボックスを、揃えの基準点を保ったまま紙面内に戻す
- 価格・商品名・店名などの短い文字は、1行に収まるように枠を広げる。入りきらないときだけ文字を小さくする
- AIが追加した装飾は、常に文字の背面に置く
- 編集後に文字どうしが重なったら、近くの空いた行へ移す。空きがなければ横に詰めて収める
- 壊れた装飾は捨て、文字や写真が壊れている案は不採用にする

### 4-5. 実行基盤：Cloud Run を選んだ理由

| 案 | 判断と理由 |
| --- | --- |
| **Cloud Run** | **採用。** Next.js のサーバー処理（AI呼び出し）をコンテナでそのまま動かせる。アクセスがないときは0台まで縮むので、デモ期間の費用がほぼかからない。サービスアカウントで Vertex AI の権限を直接管理できる |
| Firebase App Hosting | 有力な候補。ただし実体は Cloud Run の上に載る仕組みで、今回は IAM と Dockerfile を直接扱える Cloud Run を選んだ |
| App Engine / GKE / Compute Engine | 常時起動やクラスタ管理が必要で、少人数・短期間のプロダクトには過剰 |

### 4-6. データの保存先：サーバーか、ブラウザか

| 案 | メリット | デメリット | 判断 |
| --- | --- | --- | --- |
| Firestore などサーバーに保存 | 複数の端末で共有できる | ログインが必要。個人の写真をサーバーに置くことになる | 今後の拡張 |
| **ブラウザ内（IndexedDB）に保存** | ログイン不要ですぐ使える。写真がサーバーに残らない | 端末をまたいだ共有はできない（プロジェクトファイルの書き出しで対応） | **採用** |

## 5. 主な機能

- 新規作成ウィザード：用途・サイズ → 内容と写真 → 3案から選択
- サイズ：A4 / A5（縦・横）、Instagram 正方形・縦型、カスタムサイズ
- キャンバス編集：ドラッグ移動、リサイズ、整列ガイド、テキスト直接編集、レイヤー、図形・画像の追加、元に戻す／やり直し
- 日本語の指示による部分修正（変更点だけを適用）
- 日本語フォント30書体から選択（ゴシック・明朝・丸ゴシック・ポップ・手書き）。新規作成時に選ぶと、AIの提案も含めて全案に適用。Google Fonts から必要なときだけ読み込み、リポジトリには含めない
- 書き出し：PNG（印刷サイズは300dpi）、印刷用PDF（実寸mm）、再編集用プロジェクトファイル
- AIが混雑・上限・タイムアウトのときは、短い日本語で知らせ、内蔵のルールベース生成で続行

## 6. アーキテクチャ

図は `docs/architecture.png` を参照してください。

- ブラウザ：ウィザードとキャンバス編集（Next.js / React / Fabric.js）、書き出し（pdf-lib）、保存（IndexedDB）
- Cloud Run：Next.js サーバー。`/api/ai/generate` と `/api/ai/refine` で Gemini を呼び、出力を検証・修復して返す
- Vertex AI：Gemini（gemini-3-flash-preview）
- Cloud Build / Artifact Registry：ソースからコンテナをビルドして保管

## 7. 安全性・拡張性・保守性

- **安全性：** AIの認証情報はサーバー側のサービスアカウントだけが持ち、ブラウザには一切渡しません。公開リポジトリにも秘密情報はありません。入力は zod で検証し、AIの出力もスキーマで検証します。
- **費用の安全策：** Cloud Run の同時起動は最大3台。1回のAI呼び出しは45秒で打ち切ります。請求先アカウントに予算アラートを設定しています。
- **拡張性：** デザインは「仕様（JSON）」として扱うので、新しいサイズやテンプレート、AIモデルの追加がしやすい構造です。
- **保守性：** TypeScript と zod で型を揃え、Playwright のE2Eテスト20件で、作成から編集・保存・書き出しまでを通しで確認しています。

## 8. AIをどの場面でどう使ったか、なぜその場面か（採点外・必須）

> 下書きです。チームの実際の使い方に合わせて書き直してください。

- **プロダクトの中：** Gemini をレイアウト提案と日本語での部分修正に使いました。デザインの経験がない店主が、言葉だけで意図を伝えられるようにするためです。一方で、価格や店名などの事実はAIに任せず、入力値をそのまま使っています。
- **開発の中：** AIコーディング支援ツールを、実装・テスト作成・不具合調査に使いました。設計の方針、技術の比較と最終判断、AIの出力の確認はチームで行いました。たとえば Vertex AI の速度問題や、AIが返す座標の解釈違いは、実測と画面確認で原因を突き止め、対策を選びました。
